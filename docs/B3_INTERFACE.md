# B3에서 B2 엔진에 끼울 수 있는 지점

B2는 리그 평균 엔진이다. B3에서는 아래 세 지점에 선수 분포를 넣으면 같은 정확 DP가 그대로 돈다.

## 1. 타자·투수별 타석 결과 분포 q

`dp.compose_kernel(N, q, A)`는 `q`를 `[S, outs, bases, O]` 모양으로 받는다.

- `S`는 타순 슬롯 수(9)이고, `O`는 `transitions.OUTCOMES` 11개다.
- 슬롯 `s`의 타자와 현재 투수의 매치업 분포를 `q[s]`에 넣으면 된다.
- 엔진은 `Engine(R, S=9)`로 만들고 결과 `V[(inning, half)][outs, bases, d, sb, so]`를 조회한다. `sb`는 타석에 선 팀의 다음 타자 슬롯, `so`는 상대 팀의 다음 타자 슬롯이다.
- B2 테스트가 `S=9`(모든 슬롯 분포 동일)와 `S=1`의 결과가 1e-12 이내로 같음을 보장한다.

## 2. 상태 의존 투수 품질 (불펜 정책)

`Engine.solve(kernel_for)`는 하프이닝마다 `kernel_for(inning, half)`를 호출해 커널 `K[o, b, sb, o', b', r, a]`를 받는다.

- 이닝·초말에 따라 등판 투수가 달라지는 정책은 이 콜백에서 다른 `q`로 커널을 만들어 반환하면 된다.
- 점수차나 아웃에 따라 투수 교체가 달라지는 정책처럼 하프이닝 안에서도 커널이 달라져야 하면 `solve_half`의 커널 축을 확장해야 한다. 현재 엔진은 하프이닝 안에서 커널이 고정이라고 가정한다.
- 연장 이닝은 고정점 방정식으로 푼다. 따라서 이닝 10 이상의 커널은 이닝에 상관없이 같아야 한다(`kernel_for(10, h)`).

## 3. 카운트 체인

`count_chain.fit(base, q)`가 타석 결과 분포 `q[side, outs, bases, O]`와 일치하도록 카운트별 배수를 IPF로 맞춘다.

- 매치업별로 `q`를 바꾸면 같은 함수로 0-0 정합을 다시 맞출 수 있다.
- 카운트 의존성 `base`(리그 카운트별 투구 결과율)는 B3에서 타자·투수 성향으로 바꿀 수 있다.

## 그대로 쓰는 것

- 진루 테이블 `A`: 결과와 아웃·주자 상태가 같으면 선수와 무관하다고 가정한다(리그 평균).
- 타석 간 전이 `N`
- 상태 인코딩: `wp.states`
- 평가: `wp.evaluate`의 워크포워드, 블록 부트스트랩, 층화

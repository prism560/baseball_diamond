# B4 리포트 — B3 보완, 모델 결합, 구속·구종 / 당일 컨디션 게이트

> 자동 생성: `PYTHONPATH=src python -m wp.report_b4`. 수치는 모두 실행 측정값이다.

## 0. 최소 탐지 효과 크기 (작업 전 기준)

- B3 평가(7,253경기, 경기 단위 블록 부트스트랩)에서 경기 WP 로그 손실 차이의 95% CI 폭은 ±0.0015, 표준오차 약 0.00074.
- **경기 WP 수준의 최소 탐지 효과(5% 양측, 검정력 80%, 2.8×SE) ≈ 0.0021.** 이보다 작은 차이는 전체 3시즌으로도 구분할 수 없다. 아래에서 경기 수준 결과가 유의하지 않으면 '효과 없음'이 아니라 '탐지할 수 없음'으로 적는다.
- 그래서 새 기능은 먼저 타석 수준(다클래스 로그 손실/타석)에서 평가하고, **0.002 이상 개선되고 CI가 0 아래일 때만** 경기 WP 수준 재실행 후보로 올린다(승인된 기준. 매치업 q의 타석 이득 0.026이 경기 수준에서 탐지되지 않았으므로, 그 약 8%를 비용 대비 의미 있는 최소 크기로 둠).

## 2. B3 결함 수정 (1절) — 타석 수준

2023–2025 포함 경기 548,193타석, 11범주 다클래스 로그 손실. 평가 시즌마다 직전 3시즌으로 회귀 계수를 학습하고 L2 강도는 마지막 학습 시즌으로 선택.

| 변형 | 로그 손실 | B3 q 대비 [95% CI] |
|---|---:|---|
| A: B3 q (Log5, 홈구장 효과가 섞인 능력치) | 1.51304 | — |
| B: 1.1 구장 중립 능력치 + Log5 | 1.51285 | -0.00019 [-0.00025, -0.00013] |
| C: 1.2 다항 로지스틱(리그 q 오프셋) | 1.51240 | -0.00064 [-0.00074, -0.00054] |
| D: q' = 1.1 + 1.2 | 1.51237 | -0.00067 [-0.00078, -0.00056] |

- **홈런 상위 10% 과대예측 해소**: 예측/실제 0.0605/0.0525 → 0.0537/0.0535. 회귀가 홈런의 투수 계수 0.60, 구장 계수 0.76를 학습했다(Log5는 1로 고정).
- 구장 이중 반영: 쿠어스 필드(DEN02) 삼진 편향(실제−예측) +0.0114 → +0.0035; 단타는 +0.0013 → +0.0095로 오히려 커졌다. 홈/원정 공격의 범주 편향은 같은 방향·크기(홈 HR +0.0015, 원정 +0.0015).
- D − C(1.2 위에 1.1을 더한 이득) = -0.00003 [-0.00009, +0.00003]: 개선은 대부분 1.2에서 나온다.
- **게이트 1.3: q'이 B3 q보다 타석 수준에서 낫다 → q' 채택.** 다만 개선 폭(0.0007)은 3·4절의 0.002 기준보다 한 자릿수 작아 경기 수준에서 탐지될 가능성은 낮다.

## 4. B4 구속·구종 (3절)

- 상태: **미실시: Statcast(baseballsavant.mlb.com)와 MLB Stats API(statsapi.mlb.com)가 이 환경에서 차단됨. scripts/fetch_statcast.py를 로컬 PC에서 실행해 data/external/statcast/에 넣으면 진행.**
- 선수 ID 매핑: Chadwick 등록부(people-*.csv, MLBAM↔Retrosheet 24,672명) — 실시간 파이프라인과 같은 매핑.
- 연결: 경기는 (날짜, 홈 선발 투수), 타석은 경기 안 순서대로 (타자, 투수) 쌍 일치(`src/wp/statcast.py`). 연결 실패율은 데이터가 들어오면 보고한다.
- 라이브 피드 가용 여부(서빙 가능한 피처만 사용). statsapi.mlb.com도 차단되어 실제 피드로 확인하지 못했으므로 '예상'이며, 서빙 전에 실제 피드로 재확인해야 한다:

| Statcast 필드 | 라이브 피드 필드(예상) | 모델 사용 |
|---|---|---|
| pitch_type | playEvents[].details.type.code | 예 |
| release_speed | playEvents[].pitchData.startSpeed | 예 |
| pfx_x / pfx_z | playEvents[].pitchData.breaks (breakHorizontal, breakVerticalInduced) | 예 |
| plate_x / plate_z | playEvents[].pitchData.coordinates (pX, pZ) | 아니오 |
| zone | playEvents[].pitchData.zone | 아니오 |
| release_spin_rate | playEvents[].pitchData.breaks.spinRate | 아니오 |
| launch_speed / launch_angle | hitData (after contact only) | 아니오 |
| estimated_woba_using_speedangle | not in the live feed (Savant model output) | 아니오 |

- 게이트 기준: 타석 수준 로그 손실 q' 대비 0.002 이상 개선. 데이터가 없어 **미실시**이며, 서빙에는 넣지 않는다.

## 5. B4 당일 컨디션 (4절) — Retrosheet 피처(스트라이크 비율, 투구 수)

현재 투수가 이 경기에서 이 타석 전에 던진 공만 사용. 스트라이크 비율은 시즌 기준선 대비 베이지안 편차(사전 강도 k를 학습 시즌으로 선택: 50.0, 50.0, 50.0), 구속 차이는 Statcast가 필요해 제외. 해저드는 바꾸지 않는다.

| 비교 | 전체 548,193타석 | 같은 투수의 후반 타석(투구 30개 이후) 218,916 |
|---|---|---|
| q'+컨디션 − q' | -0.00060 [-0.00069, -0.00050] | -0.00087 [-0.00106, -0.00066] |
| q'+TTO − q' | -0.00056 [-0.00066, -0.00045] | -0.00077 [-0.00098, -0.00053] |
| q'+TTO+컨디션 − q'+TTO | -0.00013 [-0.00016, -0.00009] | -0.00019 [-0.00026, -0.00012] |

- **게이트 미통과**(기준 0.002): 컨디션의 이득은 유의하지만 기준의 절반 이하.
- **TTO와의 겹침**: TTO 항을 넣으면 컨디션의 추가 이득이 -0.00060 → -0.00013로 줄어 약 79%가 겹친다. 투구 수의 삼진 계수도 -0.287(TTO 없음) → -0.068(TTO 있음)로 줄었다. DP에는 이미 TTO와 강판 해저드가 있으므로 컨디션을 넣으면 이중 반영이 된다.
- 누수 테스트: 경기 안에서 이후 투구를 지워도 현재 값이 바뀌지 않음을 확인(`tests/test_condition.py`). 이 테스트가 처음 구현의 누수(리그 스트라이크 비율을 전체 데이터로 계산)를 잡아 수정했다.

## 6. 경기 WP 수준 재평가 (5절)

- 후보: q'(1절 채택) + 결합(AVG). 3·4절은 게이트를 통과하지 못해 후보에 넣지 않는다.
- **미실시 — 별도 승인 필요.** 예상 약 8–9시간(7,253경기, 경기별 저장·이어하기, 주기적 커밋). q'의 타석 수준 이득(0.0007)은 최소 탐지 효과(0.0021)보다 훨씬 작아, 경기 수준에서 B3와 구분되지 않을 가능성이 높다.

2024 시즌 10경기, 단일 스레드, float32, 점수차 ±20(재계산 ±15 변형 포함).

- 커널 캐시의 이득은 5–10%에 그친다: 시간의 대부분은 커널 조립이 아니라 선형 풀이다. **5회 이전 대타는 캐시와 ±15를 써도 5초를 넘는다.** 실시간에서는 재계산을 비동기로 돌리고, 끝날 때까지 B2E(즉시 조회)를 표시한 뒤 결과가 나오면 AVG로 바꾸는 방식을 권한다(`docs/REALTIME.md`).
- B2E는 B2 테이블 조회 + 로지스틱(마이크로초)이라 비용이 사실상 없다. AVG의 비용은 B3와 같다.

## 8. 서빙 모델 선택 (8절 규칙 적용)

1. 경기 WP 로그 손실에서 모든 후보보다 유의하게 나은 모델: **없음.** AVG는 B3·B1보다 유의하게 낫지만 B2E와의 차이(-0.00064 [-0.00161, +0.00022])는 탐지할 수 없다.
2. 불일치 시점 분석에서 체계적으로 나은 모델: B3와 B2E 사이에는 없다. **AVG는 모든 불일치 층에서 점추정이 가장 낮고, B3가 B2E보다 낮게 본 시점에서는 B2E보다 유의하게 낫다.** → 이 규칙으로 **AVG를 선택**한다.
3. (비용) AVG는 B3 엔진 비용이 들지만 7절 측정치로 실시간 기준 안에 있다.
4. (장애 대체) AVG는 B3가 실패하면 B2E로 자연스럽게 떨어진다(가중치 1−w → 1). B2E는 테이블 조회라 장애에 강하다.

**결정: 기본 서빙 모델 = AVG(B3와 B2E의 로짓 가중 평균, B3 가중치 0.55), 장애 대체 = B2E.** q'를 넣은 B3는 5절 재평가(승인 후) 결과로 교체 여부를 정한다. `docs/REALTIME.md`에 반영.
